# RailCrowd Feature Plan

## Public experience

- Homepage with train search.
- Search by train number, train name, source and destination.
- Search results with available train details and latest crowd summaries.
- Train details with route stops and coach categories.
- Coach-wise crowd report details.
- Route explorer and explanatory pages.

## Passenger experience

- Registration, login and logout.
- Submit a crowd report for a train, coach and station/segment.
- View personal report history.
- Save and unsave trains.
- View notifications and contribution history.
- Edit profile details.

## Crowd reporting

A report should include the train, coach/category, station or journey segment, crowd level, observation time and optional notes.

Initial crowd levels:
- Low
- Moderate
- High
- Very high

Reports must be timestamped and subject to freshness rules. The interface must distinguish community-reported information from official data.

## Admin experience

- Manage train, station, route and coach records.
- Review and moderate passenger reports.
- Flag suspicious or duplicate reports.
- Manage user roles and account status.
- View basic reporting and platform analytics.

## Later enhancements

- Optional external train timetable provider.
- Station/route maps.
- Saved-train crowd notifications.
- More robust report reputation and abuse prevention.
- Progressive Web App support.

## MVP boundary

The initial MVP prioritizes train search using seed data, coach-wise passenger reports, crowd summaries with freshness indicators, authentication and basic admin moderation. It will not claim access to live railway sensor data or official coach occupancy.
